# Standing code requirements

These requirements apply to every future task in this chat and every change to
this website. Keep the handover to the next group of students straightforward.

- Use the smallest clear, professional implementation that fully meets the task.
  Keep code readable; do not compress or obscure it to reduce the line count.
- Reuse existing functions, components and styles. Avoid duplicated logic,
  unnecessary abstractions, dependencies, speculative features and dead code.
- Organise code into meaningful sections with concise comment labels identifying
  the page, website element or responsibility each section implements.
- Add a short explanation where a section's purpose or a design decision needs
  context. Explain useful intent rather than narrating obvious individual lines.
- Use descriptive names and consistent formatting. Keep content, theme settings,
  evidence data and rendering responsibilities clearly separated.
- Keep shared settings in one place, especially the graphic palette and styling
  tokens. Avoid scattering configuration or repeating hardcoded values.
- Update the README's code map when file or section responsibilities change so
  the next students can find the relevant part of the website quickly.
- Review each change for unnecessary code and run checks appropriate to its
  impact before committing. Add tests for meaningful behaviour, not trivial
  implementation details.
